# システム要件定義書

## システム概要

本システムは、人間の直接的な言葉によるコミュニケーションを排し、AI（LLM）によって「動物世界の出来事やしぐさ」に翻訳・変換して流通させるスマートフォン専用のSNSプラットフォームです。既存のSNSが抱える攻撃性や「正論疲れ」という課題に対し、AIというフィルターと動物というメタファーを介在させることで、心理的安全性の極めて高い、癒やしとユーモアに満ちた公共空間を提供します。ユーザーは動物人格を持ち、時間帯を問わず自分の感情を「預ける」感覚で投稿し、他者とは数値化されない「しぐさ」を通じて緩やかに繋がります。

1. システムの目的
   - **解決する具体的な課題**: 既存SNSにおける心理的安全性不足、攻撃的な言動、数値（いいね数等）による比較ストレス、投稿への心理的ハードル。
   - **目標とする成果**: ユーザーが本音を安心して吐き出せる場の提供、通報率の極小化、夜間帯における高いユーザー定着率。
   - **期待されるビジネスインパクト**: 「世界観の純度」を維持することによる、感度の高い層へのブランド訴求、コラボ広告を通じた持続可能な収益化。

2. 主な機能
   - **コア機能**: AI動物翻訳エンジン、動物人格診断・選択システム、白いカード形式のタイムライン（森/湖）、3種限定のしぐさリアクション。
   - **差別化機能**: 「点灯」のみの非数値リアクション、行動実績に基づく「称号解放システム」、原文の完全非表示フィルタ。
   - **付加価値機能**: 空間切り替え（森/湖）による環境音・UIの変化、称号選択によるパーソナライズ。

3. 提供する価値
   - **ユーザーにとっての直接的価値**: 否定されない安心感、自分の感情が可愛い表現に昇華されるカタルシス、数値に縛られない自由な閲覧体験。
   - **ビジネスにとっての価値**: 競合他社が真似しにくい「世界観そのもの」による差別化（Moat）、課金型アバターと厳選広告による収益。
   - **社会的価値**: デジタルウェルビーイングの向上、孤独感の解消、インターネット上の優しさを育む。

4. 実現方法の概要
   - **主要なテクノロジー要素**: LLM（OpenAI GPT等）による文脈理解と変換、プロンプトをDB管理する動的インジェクション。
   - **重要なインテグレーションポイント**: AI APIとの接続（投稿翻訳時）、Clerkによるセキュアな認証。
   - **スケーラビリティへの考慮**: サーバーレスアーキテクチャによる負荷分散、Supabaseによるプロンプト・データの集中管理。

## 機能要件

### 1. ユーザー管理・認証
- Clerkを使用した認証（SNSログインまたはメール）。
- 初期診断（5問程度）の結果に基づき動物人格をレコメンド。
- ニックネーム（ひらがな・カタカナ6文字）および称号の管理。

### 2. AI動物翻訳・投稿
- ユーザー入力（原文）をAIが動物世界の内容に変換。
- **動的プロンプト管理**: 動物人格（種族・性格）ごとに独立したプロンプトテンプレートをDBで管理し、管理者が随時調整可能。
- 変換プロセスにおいて、攻撃性や不快な表現をガードレールで排除。
- 原文はDBに保存されるが、本人以外の画面には一切表示されない。

### 3. 管理者機能（非ユーザー向け）
- **プロンプトエディタ**: 各動物人格の翻訳プロンプトを編集・保存。
- **翻訳シミュレーター**: 入力したテストテキストが、各動物のプロンプトでどう変換されるかを確認・デバッグ。
- 投稿は「白いカード」UIで表示。
- 「森」と「湖」の空間切り替え機能（背景・環境音の変化）。
- ページネーションまたは無限スクロールによる投稿表示。

### 4. しぐさリアクション
- 「しっぽを振る」「毛づくろい」「のびをする」の3種。
- カウンター表示はなし。1つでもリアクションがあればアイコンが点灯。
- 自分の投稿に対して「点灯」があった場合のみ通知。

### 5. 成長システム（称号解放）
- 内部的な行動ログ（投稿数、しぐさ回数、時間帯等）を蓄積。
- 条件達成時にバックグラウンドで称号を解放。

## 非機能要件

- **パフォーマンス**: 
  - 主要画面の遷移・表示は2秒以内。
  - AI翻訳処理は5秒以内。
  - 同時接続数100人を初期目標とする。
- **セキュリティ**: 
  - 原文データへのアクセス権限管理（本人のみ）。
  - 通信の暗号化。
- **信頼性・保守性**: 
  - Vercelによる高可用性ホスティング。
  - 翻訳ロジック（プロンプト）のバージョン管理とABテスト環境。
- **ターゲット規模の根拠**: 「夜の1時間、1,000人が同時期に使う」ことを想定したインフラ設計。

## 技術スタック

推奨される技術スタックとその選定理由：

- **フロントエンド:** Next.js (React / Tailwind CSS)
  - 選定理由: スマホ専用Webアプリとしての高速なレンダリングと、開発効率の高さ。
- **言語:** TypeScript
  - 選定理由: 型定義による堅牢な開発と保守性の向上。
- **バックエンド:** Next.js App Router (Server Actions / API Routes)
  - 選定理由: フロントエンドとのシームレスな連携、サーバーレスによる運用負荷軽減。
- **データベース:** Supabase (PostgreSQL)
  - 選定理由: リアルタイム機能（しぐさの点灯など）の実装が容易で、RDBMSの堅牢性も備える。
- **認証:** Clerk
  - 選定理由: 認証基盤の構築コストを抑え、診断から登録へのスムーズな遷移を実現。
- **ホスティング:** Vercel
  - 選定理由: Next.jsとの親和性が最も高く、CI/CD環境が標準搭載されている。
- **AI:** OpenAI GPT-4o-mini (または同等の高速LLM)
  - 選定理由: 高度な文脈理解、コストパフォーマンス、レイテンシのバランス。

## 開発ロードマップ

### フェーズ 1: MVP（2ヶ月）
- **目的**: コア体験「翻訳投稿」と「しぐさ」の検証。
- **内容**: 診断、動物人格選択、AI翻訳エンジン（基本）、森のタイムライン、しぐさ（3種）、称号（初期のみ）。

### フェーズ 2: 成長・コミュニティ強化（1ヶ月）
- **目的**: 継続率向上と世界観の拡張。
- **内容**: 称号解放ロジック、湖のタイムライン、称号獲得通知。

### フェーズ 3: マネタイズ・スケーリング（以後）
- **目的**: ビジネス持続性の確保。
- **内容**: 課金動物ショップ、世界観調和型広告。

## リスク分析

- **技術的リスク**: AIの翻訳精度。意図しない変換や、元の感情を壊しすぎるリスク。
  - **対策**: プロンプトエンジニアリングの徹底と、ガードレールロジックの実装。
- **ビジネス的リスク**: ユーザー数の伸び悩み。
  - **対策**: インフルエンサーマーケティングよりも、特定のコミュニティへの丁寧なオンボーディング。
- **法的/コンプライアンスリスク**: AI生成コンテンツの権利関係、不適切投稿の管理。
  - **対策**: 利用規約の整備、通報機能（内部的）の実装。

## UI/UXの方向性

- **デザインコンセプト**: 「オーガニック・セーフティ・ミニマル」
- **トーン＆マナー**: セージグリーン基調、角丸、白い独立した投稿カード。
- **ターゲットデバイス**: スマートフォン専用。
- **参考サイト/アプリ**: Notion（清潔感）、Linear（洗練されたUI）、あつまれ どうぶつの森（空間のトーンとしぐさの概念）。
